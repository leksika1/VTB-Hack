# Безопасность

Что защищаем, от чего, какими мерами, что нашёл аудит и какие риски остаются.
Каждая мера, которую можно проверить запросом, покрыта тестом — ссылки в таблицах.

## Что защищаем

| Актив | Почему важно |
|---|---|
| Финансовые данные семьи (бюджеты, расходы, платежи) | Личная информация; утечка или подмена — прямой вред семье и репутации банка |
| Доступ к семье (токены сессий, коды приглашения) | Токен или код = полный доступ к данным семьи |
| Доступность сервиса | Семья принимает решения о покупках «здесь и сейчас» |

Персональные данные минимальны: имя, которое человек ввёл сам, и IP-адрес в журнале запросов.
Нет телефонов, паспортов, номеров карт и счетов.

## Модель нарушителя

1. **Посторонний в интернете** — перебирает коды приглашений, флудит запросами, ищет уязвимости API.
2. **Участник другой семьи** (есть свой токен) — пытается читать или менять чужие данные по их ID.
3. **Участник своей семьи** — пытается менять чужие расходы, перегрузить сервис, раздуть базу.
4. **Получивший старую ссылку-приглашение** — пытается войти в семью без ведома участников.
5. **Имеющий доступ к журналам или копии базы** — ищет в них токены и коды.

## Меры

### Доступ и аутентификация

| Мера | Где | Тест |
|---|---|---|
| Токен устройства 256 бит (`secrets.token_urlsafe(32)`); в базе — только SHA-256 | `security.py`, `models.MemberSession` | `test_tokens_are_not_exposed` |
| Каждый запрос ограничен семьёй из токена; чужой объект = «не найден» (404), без подсказок о существовании | `services/*` | `test_families_are_isolated` |
| Менять и удалять расход может только автор | `services/finance.py` | `test_update_expense_errors`, `test_delete_expense` |
| Сессия закрывается после 90 дней без запросов и при выходе из семьи | `deps.resolve_member`, `maintenance.py` | `test_inactive_session_expires`, `test_leave_family_*` |
| Код приглашения можно сменить — старые ссылки перестают работать | `POST /api/family/invite-code` | `test_rotate_invite_code` |
| Код приглашения: 6 символов без похожих букв (32⁶ ≈ 10⁹) + лимит 20 попыток/мин с IP | `security.py`, `ratelimit.py` | `test_rate_limit_on_invite_codes` |
| Ключ идемпотентности: ≥ 16 символов, криптослучайный (`crypto.randomUUID`); для анонимных запросов привязан к IP | `deps.py`, `services/families.py`, `useRequestId` | `test_anonymous_idempotency_key_is_bound_to_client_ip`, `test_short_idempotency_key_is_rejected` |
| Токен в заголовке `Authorization`, не в cookie — CSRF неприменим; CORS только для `CORS_ORIGINS` | `main.py` | `test_cors_*` |

### Ввод данных

| Мера | Тест |
|---|---|
| Все SQL-запросы через ORM с параметрами — инъекции невозможны | весь набор e2e |
| Строгие проверки полей: длины, категории из списка, даты, суммы > 0, ≤ 2 знаков, ≤ 100 млн | `test_*_validation` |
| Деньги в целых копейках — нет ошибок округления и «отрицательных нулей» | `test_amount_with_kopecks_is_exact` |
| Тело запроса ≤ 64 КБ (backend), ≤ 128 КБ (nginx); тело без `Content-Length` отклоняется | `test_request_body_size_limit`, `test_body_without_length_is_rejected` |
| Ошибки не раскрывают внутренности: единый формат, трассировка только в журнал | `test_unknown_route_returns_json_error` |
| XSS: React экранирует вывод, `dangerouslySetInnerHTML` не используется; CSP запрещает чужие скрипты | — |

### Защита от перегрузки и DDoS (по уровням)

```
Интернет → [хостинг / анти-DDoS L3-L4] → Traefik (TLS) → nginx → backend → PostgreSQL / Redis
```

| Уровень | Мера | Значение по умолчанию |
|---|---|---|
| Хостинг / банк | Объёмные атаки (L3/L4, SYN-flood) отражаются на сети провайдера или анти-DDoS банка — приложению это не по силам | — |
| nginx | `limit_req` на IP для `/api` | 20 запросов/с, всплеск 40 |
| nginx | `limit_req` на IP для статики | 50 запросов/с |
| nginx | `limit_conn` на IP | 50 соединений, 10 потоков событий |
| nginx | Таймауты медленных клиентов (slowloris) | заголовки и тело 10 с |
| nginx | Реальный IP из `X-Forwarded-For` только от прокси из частных сетей | — |
| backend | Лимиты по смыслу в Redis (скользящее окно, общие для всех копий) | приглашения 20/мин/IP, регистрация 10/мин/IP, запись 120/мин и чтение 600/мин на участника |
| backend | Потоков событий на участника | 5 |
| backend | Записей у семьи (расходы, платежи отдельно) | 20 000 |
| backend | Участников в семье | 10 |
| uvicorn | `--limit-concurrency`: лишние соединения сразу получают 503 | 1000 на копию |
| PostgreSQL | `statement_timeout` и `idle_in_transaction_session_timeout` | 5 с и 15 с |
| пул БД | Нет свободного соединения 5 с → 503 «Сервер перегружен», а не очередь | 10 + 20 на копию |
| контейнеры | Лимиты памяти и числа процессов | backend 512 МБ / 1 CPU, БД 1 ГБ, Redis 128 МБ, nginx 128 МБ |

Тесты: `test_rate_limit_*`, `test_read_rate_limit_per_member`, `test_event_streams_per_member_are_capped`,
`test_records_per_family_are_capped`, `test_family_member_limit`.

Если Redis недоступен, лимиты backend временно не действуют (запросы пропускаются, ошибка пишется в журнал):
лучше пропустить лишний запрос, чем положить сервис. nginx-лимиты при этом работают.

### Данные и инфраструктура

| Мера | Где |
|---|---|
| PostgreSQL и Redis — во внутренней сети `data` без выхода наружу; nginx в неё не входит | `docker-compose.yml` |
| Пароли PostgreSQL и Redis обязательны — без них стек не запускается | `docker-compose.yml` |
| Redis хранит только временное (счётчики, события) и не пишет на диск | `docker-compose.yml` |
| backend работает не от root; во всех контейнерах `no-new-privileges` | `backend/Dockerfile`, `docker-compose.yml` |
| Ответы API: `Cache-Control: no-store`, `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer` | `middleware.py`, тест `test_api_security_headers` |
| Фронтенд: CSP без внешних источников, запрет встраивания во фреймы, HSTS, `Permissions-Policy` | `frontend/Dockerfile` |
| Нет обращений во внешние сервисы (шрифт в бандле, не с Google Fonts) — IP пользователей никуда не уходит, работает в закрытом контуре | `frontend/src/main.tsx` |
| Журнал без тел запросов и токенов; коды приглашений в путях заменяются на `***` | `middleware.py` |
| Swagger можно выключить (`ENABLE_DOCS=false`) | `main.py` |

## Остаточные риски и что сделать к пилоту

| Риск | Рекомендация |
|---|---|
| Токен лежит в `localStorage` и доступен скрипту на странице при XSS (CSP снижает риск) | В пилоте — вход через ВТБ Онлайн (OIDC) и сессия в `HttpOnly; Secure; SameSite=Strict` cookie |
| Любой взрослый может исключить другого взрослого (ролей «владелец» нет) | Если понадобится — роль владельца семьи с правом исключать взрослых |
| Объёмный DDoS (L3/L4) приложение не отражает | Анти-DDoS хостинга / банка, WAF перед Traefik |
| IP-адреса в журнале — персональные данные по позиции РКН | Срок хранения журналов ≤ 30 дней, доступ по ролям; или усечение последнего октета |
| nginx запускается мастер-процессом от root | Образ `nginxinc/nginx-unprivileged` |
| Бэкапы БД не зашифрованы (см. OPERATIONS.md) | Шифрование при хранении, отдельное хранилище, регулярная проверка восстановления |
| Лимиты backend не действуют при недоступном Redis | Redis Sentinel; алерт по `/api/ready` |

## Как проверить самостоятельно

```bash
cd backend
pip-audit -r requirements.txt                 # уязвимости Python-зависимостей
pytest -q tests/e2e/test_security.py tests/e2e/test_hardening.py
cd ../frontend && npm audit
```

Сообщить об уязвимости: напишите участникам команды напрямую, не через публичные issue.
