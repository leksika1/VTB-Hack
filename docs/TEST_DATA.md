# Тестовые данные

Как показать приложение без ручного ввода: что лежит в демо-семье, как поднять постоянную тестовую семью
на сервере, тестовые входы и готовые файлы для проверки импорта и чеков. Все данные вымышленные.

## Два варианта

| | Демо-копия | Витрина на сервере |
|---|---|---|
| Как попасть | Кнопка «Посмотреть на примере демо-семьи» (`POST /api/demo`) | «У меня есть код» → код витрины; или «Войти через ВТБ ID» → тестовый логин |
| Кому | Каждый посетитель получает **свою** копию | **Одна** семья на сервер, общая для всех |
| Живёт | 24 часа (`DEMO_TTL_HOURS`) | Пока не пересоздадут |
| Переключение участников | Кнопкой в демо-режиме | Отдельный вход за каждого участника |
| Для чего | Посмотреть самому, можно ломать | Показ жюри: двое на разных устройствах видят изменения друг друга сразу |
| Изоляция | Песочница: никто не войдёт по коду, ВТБ ID и почта не привязываются, «Выйти из демо» возвращает в свою семью | Настоящая семья на сервере: выход из неё — настоящий |

## Состав семьи (одинаковый в обоих вариантах)

Даты считаются от дня создания: «сегодня», «через 2 дня» и т. д.

## Витрина на сервере

### Создать и получить коды

Dokploy → сервис **Backend** → **Terminal** → контейнер `backend`:

```bash
python -m app.seed --reset
```

Команда печатает:

```
Витрина создана
Код семьи (вход взрослым): GL3XSC
Детский код (вход ребёнком): 79PMPV
Вошедшие по коду видят данные после подтверждения: Петя или Маша → вкладка «Семья»
```

- **Код семьи** вводится на экране входа во вкладке «У меня есть код» (или ссылкой `https://<домен>/?invite=<код>`):
  входите новым **взрослым** участником. Удобно раздать жюри.
- **Детский код** — так же, но входите **ребёнком** (видны только свои карманные деньги и запросы).
  Оба кода постоянные и многоразовые; повторный запуск команды печатает те же коды.
- **Вход надо подтвердить.** Пока взрослый не подтвердит, вошедший видит пустую семью. Подтвердить: войти как
  `petya` или `masha` (ВТБ ID) → заявка в `GET /api/family` → `pendingMembers` →
  `POST /api/family/members/{id}/approve`. Это же хороший сценарий показа: «посторонний с кодом ничего не видит».
- Постоянный код семьи вместо случайного: переменная `SHOWCASE_INVITE_CODE=VTBDEM` (6 латинских букв/цифр).
  Не публикуйте его: кто знает код, может войти в витрину.
- В семье не больше 10 участников. Если жюри «заполнило» витрину — `python -m app.seed --reset`.

### Вход через тестовый ВТБ ID (когда во фронтенде будет кнопка)

Dokploy → Environment сервиса backend:

```
SEED_SHOWCASE=true                # необязательно: создать витрину при старте, если её нет
OIDC_ENABLED=true
OIDC_MOCK=true
OIDC_ISSUER=https://<домен фронтенда>/api/mock-idp
OIDC_CLIENT_ID=family-budget
OIDC_REDIRECT_URIS=https://<домен фронтенда>/auth/callback
```

- `SEED_SHOWCASE=true` — при старте backend создаёт витрину, если её ещё нет. Повторные запуски и несколько копий
  backend безопасны: у витрины фиксированный id.
- `OIDC_MOCK=true` включает **тестовый** вход через ВТБ ID: страница «войти как…» без пароля, логины из таблицы выше.
  Это только для демо-сервера — в контуре банка его не включают (подробнее — [FEATURES.md §11](FEATURES.md#11-вход-через-втб-id)).
- `OIDC_REDIRECT_URIS` — адрес страницы фронтенда, которая принимает `code` и `state` и вызывает
  `POST /api/auth/oidc/callback`.

### Обновить даты перед показом

Данные витрины привязаны ко дню создания. Чтобы «сегодня» снова было сегодня — пересоздать:

```bash
docker compose exec backend python -m app.seed --reset
```

В Dokploy — вкладка сервиса backend → **Terminal**, та же команда без `docker compose exec backend`.
Пересоздание закрывает старые сессии витрины: войти заново тем же логином.

### Локально

```bash
cd backend
python -m app.seed --reset
```

## Коды подтверждения e-mail

С `EMAIL_BACKEND=outbox` (по умолчанию) письма не отправляются, а складываются в таблицу `email_outbox`.
Код подтверждения адреса для тестов:

```sql
SELECT to_email, body, created_at FROM email_outbox ORDER BY created_at DESC LIMIT 5;
```

## Что не входит в тестовые данные

- Реальные банковские данные и персональные данные людей — их нет нигде в репозитории.
- Импорты, цели и уведомления в витрине не создаются заранее — их удобнее показать «вживую».
